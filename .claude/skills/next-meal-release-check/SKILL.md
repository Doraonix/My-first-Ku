# 下一餐｜发布前检查

用一条命令把五项检查跑完，给出每项“通过 / 失败”和总结论。结论以脚本实际输出为准，AI 不得根据旧结果、推测或部分输出改写。

## 使用前确认

- 遵循项目 AGENTS.md、CLAUDE.md 和当前任务。本 Skill 不授权部署、提交、推送或修改项目文件；查出问题只报告，修不修由用户决定。
- 脚本会发出只读 GET 请求，只发往两个网站：
  - 前端网站：`check.mjs` 里的 `FRONTEND_ORIGIN`。请求它的 `/next-meal/` 首页，以及首页引用的、同一网站上的 JS 和 CSS。具体文件名以运行时首页里写的为准。
  - 接口网站：`recipe-data.mjs` 里的 `API_BASE_URL`。请求 `/api/health`、`/api/recipes`、`/api/recipe-materials`。
  - 不登录、不带凭据、不访问 `/api/favorites`、不写数据。
  - 遇到跳转时先看要跳去哪：同一网站内的跳转照常跟过去；要跳到别的网站，或首页引用了别的网站的文件，都不去请求，直接判失败。
  - 运行 `npm test` 和构建时关掉了 npm 每周一次去 npm 官网查新版本的请求，所以运行中只会访问上面两个网站。
- 项目规定“真实请求由用户操作”（CLAUDE.md），所以**默认由用户在自己的终端运行，再把输出贴回来**。只有用户在这次对话里明确要求 AI 来跑，AI 才运行。调用本 Skill 本身不算同意。
- 运行会执行 `npm test` 和正式构建。构建输出到系统临时目录，不覆盖项目里的 `dist/`；系统临时目录如果在项目里面，第 5 项直接失败、不构建。正常结束后只删除本次创建的那个临时目录。

## 运行

在项目根目录执行（Windows PowerShell 5.1 也可以；运行的是 Node，不需要改执行策略）：

```powershell
node .claude/skills/next-meal-release-check/check.mjs
```

- 接着用 `$LASTEXITCODE` 看退出码：0＝可以发布；1＝不可发布；2＝脚本自身出错或没跑到结论，同样不可发布。
- 直接在窗口里看输出，中文正常。在 Windows PowerShell 5.1 里如果要把输出存文件、用管道传给别的命令或存进变量，先执行 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`，否则中文会乱码。乱码不影响退出码。
- 耗时主要在测试和构建，正常一分钟内。每条命令最多等 5 分钟，超时会结束整组进程并判为失败。测试和构建都卡住时，整次运行可能超过 10 分钟。

## 五项检查与判定

| # | 检查项 | 通过条件（缺一条就算失败） |
| --- | --- | --- |
| 1 | 公网首页 | `/next-meal/` 首页返回 200，没被跳到别的网站，页面**标题**含“下一餐”。首页引用的 JS、CSS（包括 preload；属性值加不加引号都认）各至少一个，都在同一网站上、都返回 200、内容类型确实是 JS 或 CSS（防止找不到文件时返回网页冒充），并且内容不为空 |
| 2 | 公网读接口 | 三个接口都返回 200 的 JSON 且 `ok:true`；health 的 `service` 为 `next-meal`；菜品、材料的 `data` 是非空列表；网页实际读取的这两个接口允许首页跨域读取（health 网页不调用，不查跨域） |
| 3 | 密钥 | 扫描范围：①假如现在执行 `git add .` 会被收进去的全部文件（脚本只列清单，不会真的执行 git add）；②暂存区里还没提交的内容；③第 5 项本次构建出的文件；④Git 所有分支和标签的历史提交，包括新增的行和提交说明。六条规则要零命中。另外，`.env` 类文件不会被提交，并且是**项目根目录的 `.gitignore`** 让 Git 忽略 `.env` 和 `.env.local`，这个 `.gitignore` 本身也会被提交；只靠本机 `.git/info/exclude`、全局设置或不会被提交的 `.gitignore` 都不算 |
| 4 | 自动测试 | `npm test` 退出码 0，测试数大于 0，并且全部通过：失败、取消、跳过、待办都为 0 |
| 5 | 正式构建 | 构建退出码 0；产物只有 `index.html` 和 `assets/`；`index.html` 里引用的 JS、CSS 各至少一个；所有 `<script src>`、`<link href>` 的路径都以 `./assets/` 开头，并且文件确实存在 |

第 1、2、4 项有几处比最初定的更严：标题而不是页面任意位置、资源内容不为空、health 的 `service`、跳过和待办也要为 0。这些在 Day 25 经用户确认保留。

### 密钥规则与扫描方式

六条规则写在 `check.mjs` 的 `SECRET_RULES`：

1. 腾讯云 SecretId：AKID 开头的长串。
2. SecretKey 或 SessionToken 后面直接跟着 16 位以上的值：赋值、JSON（包括转义引号的 JSON 字符串）、YAML、`$env:` 写法，以及 `setx` 和 `SetEnvironmentVariable` 两种设置环境变量的写法。只出现字段名不算。
3. 私钥文件头。
4. 三段式登录令牌（JWT）。
5. 带“用户名:密码@”的数据库连接串，只认 postgres、postgresql、mysql、mongodb、mongodb+srv、redis 这六种协议名。
6. 写死的密码：名字**以** password、passwd 或 pwd **结尾**（DB_PASSWORD、PGPASSWORD、dbPassword 也算）。值有三种写法会被查到：加引号的值（包括转义引号的 JSON 字符串）、紧跟等号的值（以 `$ % { <` 开头的变量引用除外）、像 SQL 那样的“PASSWORD 加单引号值”。值至少 4 个字符，且不含空格。

几点说明：

- SecretId 只由第 1 条判断，所以测试里 `TENCENTCLOUD_SECRETID` 的假值不会误报。
- 命中时只显示位置、规则名和长度，不显示内容。最新提交说明如果像有密钥，开头也只显示提交号。本文件和 README 描述规则时不写成能被规则命中的样子，避免查到自己。
- 不跳过任何文件。带 BOM 的 UTF-16 文件（Windows PowerShell 5.1 用 `>` 存出来的就是这种）按 UTF-16 读一遍，再按单字节去掉 0 字节读一遍，这样后来用别的程序追加的英文也能查到。其余含 0 字节的文件（无 BOM 的 UTF-16、UTF-32、二进制）按单字节读并去掉 0 字节，里面的英文密钥照样能查到。Git 历史和暂存区用 `--text` 读，二进制差异也会扫。
- 已从工作区删掉、但 Git 还在跟踪的文件，计为“已删除”。它以前提交过的内容在历史里扫，暂存区里还没提交的内容在暂存区里扫。其他读不出来的文件（例如被别的程序锁住）直接判失败。
- 嵌套的 Git 仓库或子模块：`git add` 只记录它的提交号，里面的文件不会进本项目，所以只在报告里注明，不扫描、不判失败。
- 提交说明里折成几行的一段，会连成一行再扫一遍。读 Git 历史时固定了几项设置（列出第一个提交的内容、显示完整提交号、固定输出格式），不受本机 Git 配置影响。

已知查不到的情况：

- 名字在 password 后面还有别的字，例如 PASSWORD_PROD、adminPasswordValue。
- 等号两边有空格、值又不加引号的写法；YAML 里不加引号的值；值里带空格；值不足 4 个字符。不查这几种，是为了不把“密码 = 变量名”“密码输入框提示文字”这类代码误报成密码。
- PowerShell 里 `ConvertTo-SecureString` 后面直接写的明文。项目自己的离线测试脚本就用这种写法放了一个假值，如果加进规则，就要为它开豁免。
- 上面六种以外的连接串协议，以及规则以外的其他平台密钥格式。
- 项目里原有的 `dist/` 不扫描，脚本只扫本次新构建出的那一份。上传前请重新执行 `npm.cmd run build`，不要上传旧的 `dist/`。

## 防虚报规则

- 每项只有“通过”和“失败”。没跑成、超时（每个请求 10 秒，每条命令 5 分钟）、读不懂返回或输出、因为在别的网站上而没去请求的文件，都算失败。不设“跳过”“警告”。
- 只有五项全部通过，结论才是“可以发布”。第 5 项失败时第 3 项也会失败，因为本次构建出的文件没扫到。脚本一开始就把退出码设为 2，只有走到“可以发布”那一行才改成 0。
- 不重试：失败就如实报告，不“再跑一次碰运气”。
- 豁免清单：**无**。`check.mjs` 不读取任何豁免清单。不得为了让检查通过而放宽规则、改测试或改判定。确实需要豁免时，先经用户批准，再同时修改 `check.mjs` 和本文件，并在这里逐条写明文件、规则和理由。
- 检查项、规则或网站地址要改，先经用户确认，再同步修改本文件和 `check.mjs`。

## AI 调用步骤

1. 说明正在使用 next-meal-release-check，完整读取本文件，确认工作目录是项目根目录。
2. 告诉用户运行命令和会访问的两个网站，请用户在自己的终端运行，并把从分隔线开始的输出和 `$LASTEXITCODE` 贴回来。用户在这次对话里明确要求 AI 来跑时，才由 AI 运行。AI 运行时一律放到后台运行，等它自己结束；不要在前台用 10 分钟的工具超时，因为整次运行可能超过 10 分钟。
3. 原样贴出报告和结论行，并报告退出码。不要只说“通过了”。没看到“结论：”那一行（比如中途被打断），就按“没跑完＝不可发布”报告，并告诉用户系统临时目录里可能留下一个 `next-meal-release-check-` 开头的文件夹。
4. 有失败项时：逐项说明失败原因和可能的问题位置，然后停下，等用户决定。不自动修复、不重跑、不部署。
5. 用户要求记录时，在项目 README 当天的记录里写入日期、命令、各项结果和结论，不预填“通过”。

## 不能证明的事

- 浏览器里的真实显示和操作。本脚本只读 HTML、资源文件和接口返回。
- 收藏接口、登录和任何写入。这些需要另外的授权和验证。
- 公网是否已经是最新版本。这属于发布后核对，不在本检查里。
- 项目里原有的 `dist/` 是否安全、是否最新。脚本只检查本次新构建的那一份。
- 密钥扫描只覆盖上面六条规则和写明的范围。零命中不等于绝对没有敏感信息。
- 只在 Windows 上实测过。超时后结束整组进程用的是 Windows 自带的 taskkill；在其他系统上只结束直接启动的那一个进程。
